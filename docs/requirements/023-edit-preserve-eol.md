## 背景

需求 010 采用 dsh 方案：`edit` 读入时把 CRLF 归一到 LF，替换后按"主导格式"恢复全文。
其验收标准明确写了「混合文件被规整成主导格式（dsh 行为）」，代码注释也是「编辑即清理」。

但这对**混合换行符文件**是破坏性的：只要文件里 CRLF 和 LF 并存（哪怕只编辑一行），
`restoreLineEndings` 会把**全文**统一成主导格式，改动了大量未编辑区域的行尾，
导致 diff 噪音巨大，且可能违反项目自身的 .gitattributes 约定。

## 目标

`edit` 编辑混合换行符文件时：
- **只改被替换的文本**，未编辑区域的行尾**原样保留**
- 纯 LF / 纯 CRLF 文件行为不变

## 方案

替换时不再对全文做统一归一+恢复，而是**按匹配位置局部处理**：
- 在 LF 世界定位 `oldNorm` 的每一处
- 记录该处在原文中对应的原始字节区间及其行尾风格
- 只替换命中区间，其余原样保留

实现要点：
- 需要一个"LF 索引 → 原文索引"的映射（因原文 CRLF 占 2 字符，LF 世界占 1 字符）
- `newString` 的行尾风格跟随**被替换处**原有风格

## 验收标准

- [ ] 混合文件编辑后，未编辑区域行尾不变（逐字节对比）
- [ ] 纯 LF 文件编辑后仍为 LF
- [ ] 纯 CRLF 文件编辑后仍为 CRLF
- [ ] 新增/更新单元测试覆盖混合场景
- [ ] typecheck / test / lint 全绿

## 遗留 / 后续

- 需求 010 的"编辑即规整"行为被本需求取代，需在 010 档案标注
