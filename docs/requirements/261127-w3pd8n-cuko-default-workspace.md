# Cuko 未选工作区时使用默认工作区（保证首条消息带系统提示词）

## 背景

系统提示词只在会话的第一条消息里发一次：

- Cuko 协议：`withSystemPrompt` 在没有 projectDir 时直接跳过。
- OpenAI 协议：`buildSystemPromptText` 没有 projectDir 返回空串，第一条用户原文不带提示词就写入数据库，之后不再修改（前缀缓存）。

所以没绑定工作区的会话，第一条消息不带系统提示词，之后也补不回来：AI 不知道有 cuckoo 工具。工具里的相对路径也没有根目录。

## 1. 已确定的决定（2026-11-27）

| # | 问题 | 决定 |
|---|---|---|
| 1 | 默认目录位置 | `<安装目录>\cuko-default-workspace`（exe 所在目录）。开发版（npm start）或安装目录写不进去时，退回 `<userData>\cuko-default-workspace`；弹窗显示实际使用的完整路径 |
| 2 | 提示方式 | 发送时当前会话没绑定工作区，每次都弹窗：「选择项目目录…」（主按钮，选好后绑定并发送）/「使用默认目录并发送」/ × 或 Esc 取消（不发送，输入框内容保留） |
| 3 | 卸载 / 升级可能删除默认目录的提醒 | 第一版不加，看效果再定 |
| 4 | 已经没带提示词发出的旧会话 | 不补、不提示 |

## 2. 行为规则

- 选「使用默认目录」：目录不存在就创建；第一次使用时加入工作区列表（名称「默认工作区」）；把当前会话绑定到它，再发送。
- 选「选择项目目录…」：打开系统选文件夹窗口；选好后加入工作区列表（已在列表里就直接用）、绑定会话、发送；选文件夹时取消则不发送，弹窗保留（可改选默认目录或取消）。
- 主进程兜底：`startCukoRun` 发现会话没有 project_dir，自动绑定默认目录并写回数据库，保证第一条消息带系统提示词（防止页面漏掉）。
- 会话正在运行时（回复中排队）不弹窗。
- 实现：空闲发送也经过队列接口，没有项目目录时队列接口抛错，assistant-ui 把消息（含附件）退回输入框，再弹窗；绑定目录后调用 composer.send() 重新发送。

## 3. 实现（初稿，读完代码后细化）

- 主进程：默认目录解析函数（安装目录优先 → 可写探测 → 退回 userData → 创建目录）；IPC 读取默认目录、给会话绑定默认目录。
- 页面：`sendNow` 前检查当前会话 / 当前工作区；新弹窗组件。
- 测试：目录选择与回退（打包 / 开发版 / 不可写）；`startCukoRun` 兜底后第一条消息带系统提示词（两种协议）。

## 4. 追加（2026-11-27）：没有默认打开的窗口时只打开 Cuko 窗口

- 启动：有勾选「默认打开」的网页版窗口 → 照旧打开，Cuko 窗口随后不抢焦点打开；一个都没勾（含新用户）→ 只打开 Cuko 窗口并聚焦，不再打开选择平台页。
- Cuko 页面文件缺失或窗口创建失败：没有任何网页版窗口时退回打开一个（避免启动后看不到窗口）。
- 再次启动（second-instance）/ Mac 点 Dock（activate）：没有网页版窗口时打开或聚焦 Cuko 窗口。
- Cuko 窗口左下角新增「打开网页版窗口」：已有网页版窗口就聚焦，没有就按默认规则（上次活跃 / 第一个）打开；接口 `cuko:open-web-window` 只接受 Cuko 窗口的请求。
- 只开 Cuko 窗口时，关掉它程序正常退出（window-all-closed 逻辑不变）。
