# v0.9.0 — Cuko API 正式版

> 0.9.0 的核心是 **Cuko API**：一个完全独立的 Cuko 工作窗口，加上一套面向 **Stateful Provider** 的
> 增量交互协议。它不是主界面的替代，而是与你原有的工作方式**并行**的第二种入口。
>
> 自 v0.8.22 之后，本次是正式版（0.9.0），beta.1 期间暴露的几处关键缺陷已全部修复。

本次亮点速览：

1. **全新的 Cuko 独立窗口** —— 项目/会话两级树、工作区、附件、主题跟随，与主界面完全隔离。
2. **Cuko API v1** —— 只发增量输入，由 Stateful Provider 维护上下文，SSE 流式返回。
3. **后台运行** —— 运行循环搬到主进程，关掉窗口任务继续跑，多个会话可同时运行。
4. **切换模型不丢上下文** —— 历史压缩成一次 `type:"compress"` 请求；压缩回复里的工具调用也会继续执行。
5. **Cuko API 市场** —— GitHub `topic:cuko-api` 发现仓库，一键跳到主页看 README 自行部署。
6. **长会话可用性** —— 虚拟列表、请求日志、本地时间戳、上下文用量、无模型引导。

## 🪟 Cuko 独立工作窗口

- 首页「**Cuko 模式**」打开独立窗口；应用启动时也会自动打开（`showInactive`，不抢主窗口焦点）。
- 左侧改为 **项目 → 会话** 两级树：项目可展开 / 归档 / 重命名 / 打开系统文件夹 / 在该项目下新建对话。
- 会话支持归档、重命名、删除；**已归档内容默认收起**，可展开查看；归档项目整组移入「已归档项目」区。
- 工作区选择与主程序一致；**切换工作区会把当前会话迁移到新项目目录**（不再出现左边仍挂在旧项目下）。
- **附件持久化**：发送时原文件落盘到 `<userData>/cuko-attachments/...`，历史消息只存相对路径；
  图片显示缩略图，其他文件显示文件名卡片，换模型 / 换供应商后仍可回看。
- 主题跟随主程序：深色 / 浅色 / 跟随系统实时同步，不会出现深色下白底闪烁。
- 输入框下方显示**上下文 token 用量**；没有配置任何模型时，输入框旁显示「设置模型」按钮。

## 🔌 Cuko API v1

协议见 `docs/protocols/cuko-api-v1.md`，客户端实现了：

- `GET /v1/models`：拉取模型目录，支持 Bearer Token。
- `POST /v1/responses`：SSE 流式对话；事件 `message` / `done` / `error`。
- **会话续接**：首次请求不带 `providerSessionId`，服务端在第一帧返回；后续请求带上它续接状态。
- **请求来源标记**：请求外层 `type` 区分 `"user"`（用户输入）/ `"tool"`（工具执行结果）/
  `"compress"`（切模型历史压缩）；`input` 元素统一是 `text` / `file`。
- **首轮系统提示词**：按 `# ` 分段后放在用户输入前；续接对话不重复发送。
- **工具执行循环**：自动提取回复里的 `cuckoo` 代码块，逐个执行，结果以 `type:"tool"` 回传；
  **不设轮数上限**，只要模型继续输出代码块就继续执行。
- **接入说明**：设置 → Cuko API 底部「如何接入 Cuko API」：
  - 三步接入 + 协议速览
  - 可直接复制给 AI 的开发提示词
  - 构建时内联的完整接口文档（与 `docs/protocols/cuko-api-v1.md` 同步）

## 🛒 Cuko API 市场

设置 → Cuko API →「发现 Cuko API 市场」，按 GitHub `topic:cuko-api` 搜索。

- **唯一真相源是 topic**：搜不到就如实返回空，不做关键词兜底、不做官方精选清单。
- 卡片展示仓库名、描述、Star 数与更新时间。
- 点卡片或「**进入 GitHub**」按钮 → 用系统浏览器打开仓库主页，**由你按 README 自行部署**，
  再回到设置页手动「添加模型提供商」填入地址。
- 说明：市场**不会**替你把仓库地址写进 Provider 配置（GitHub 仓库地址不是 API 地址）。

## 🔁 模型切换与上下文

- 会话内可随时切换模型；有历史消息时会先确认「历史会发给新模型，产生未命中缓存的 token」。
- 确认后把历史压缩成一次 `type:"compress"` 请求：
  - 每条历史消息一个 `text` 元素，带「用户:」「助手:」「工具:」前缀
  - 不发送 `think`
  - 不涉及 `edit` / `deleteFile` 的工具结果替换为固定文案（避免把过期结果喂给新模型）
  - 重新补发留档的系统提示词
- **成功后才切换** `provider_id` / `model_id` / `provider_session_id`；失败保持旧绑定，可重试。
- 压缩请求的回复同样落库并显示；如果回复里带 `cuckoo` 工具块，会**自动执行工具**并以
  `type:"tool"` 继续对话，不会停在「模型回复了但工具没跑」。

## 🚀 后台运行与可靠性

- 运行循环从渲染进程搬到主进程：每个会话一个运行实例，可多会话并行；
  关闭 Cuko 窗口不中断，重新打开后从 `getRuns` 快照恢复进行中的消息。
- 同一会话同时只允许一个运行；删除会话会先取消运行，避免后台继续写库。
- 侧边栏正在后台运行的会话显示转圈。
- **请求日志**：主进程保留最近 100 次请求，页面内可查看时间、类型、模型、`type`、
  input 条数 / 字数、HTTP 状态、providerSessionId、耗时与错误（这些在 DevTools Network 里看不到）。

## 🐞 本次正式版修复（beta.1 之后）

这几条都是会让你「以为功能没做」的硬伤，本次全部修掉：

- **点击会话不切换** —— `switchThread` 里引用了一个未声明的 `runtimeRef`，每次点击都在
  更新会话 ID 之前抛 `ReferenceError`。已补声明，同时把「切换会话时保存 / 还原输入框草稿」真正接通
  （之前只写不读，是死缓存）。
- **`cuckoo` 代码块不执行（带属性）** —— 模型把围栏写成「三个反引号 + cuckoo + `id="…"`」时，
  旧逻辑把整行 `cuckoo id="58216"` 当语言标记和 `'cuckoo'` 严格比较，块被整条丢弃。
  现在语言标记只取第一个 token，并识别 `cuckoo-js` / `cuckoo_js` 等变体。
- **`cuckoo` 代码块不执行（围栏挤在正文里）** —— 模型偶尔把开围栏贴在正文行尾
  （`……确保流程。` 后面紧跟三个反引号和 `cuckoo`），按行首匹配会整块漏掉。
  现在按「围栏可出现在行内任意位置」扫描，主进程与渲染层两条路径都已修正。
- **市场「进入 GitHub」点了没反应** —— 设置弹窗在 Cuko 独立窗口里运行时，该窗口的 preload
  没有暴露 `openExternal`，而 `window.open` 又被窗口策略 deny，点击完全无响应。
  已给 Cuko 窗口补上 `openExternal`；按钮尺寸也从撑满整行改为贴合内容。

## ⚡ 长会话与体验细节

- **虚拟列表**：Cuko 消息列表按视口渲染，实测 300 条消息只保留约 13 个 DOM 节点。
- 修复发送消息后滚动位置跳动；新用户消息强制贴底，流式回复只在原本贴底时跟随。
- 思考块流式展开、结束后折叠；`cuckoo` 代码块默认折叠、可展开复制；
  多个工具调用合并到同一消息，工具卡片折叠时展示参数摘要。
- 输入框外壳去边框、内边距收紧，上下文用量贴近输入框。

## 🧰 工具契约精简

- 系统提示词里的工具 SDK（`src/tools/api.d.ts`）从 **20.6KB 压到 9.9KB（约 -52%）**。
- 每个工具只保留一段简洁的 `doc`，删除了与 `doc` 重复的 `usage`、`@param`、`@returns`、`@throws`；
  `read` / `edit` 的空白与行号注意事项、`bash` / `pwsh` 的编码与退出码等关键约束保留。
- 运行时行为不变，只是提示词更短、更少重复。

## 🔧 其他改动

- **Electron 44 → 45**，React 18 → 19；Cuko 窗口引入 assistant-ui + Tailwind 4 独立打包链路。
- **时间戳**：Cuko 表统一写「本地时间 + 偏移」ISO（如 `2026-11-19T12:05:45.216+08:00`），
  直接打开 SQLite 不再看到 UTC 的 `Z`。
- **系统提示词留档**：首轮注入的完整提示词同时写入 `cuko_sessions.system_prompt` 与
  `cuko_messages`（role=system），聊天页折叠展示，会话菜单可查看。
- **会话 ID 可改**：会话菜单支持修改 `providerSessionId`；深色模式下弹窗文字可读性已修。
- **用量统计**：补齐缺失时间段，修复切换时间范围后旧请求覆盖新结果的竞态。
- **剪贴板恢复**：弃用 `clipboard.write`，恢复时直接 `writeText` 写纯文本，修复恢复失效。

## 📦 安装

- **Windows**：下载 `cuckoo-code-win-v0.9.0.exe`（安装版，支持自动更新）。
- **macOS**：下载对应架构的 `.dmg`（Intel 选 x64，Apple Silicon 选 arm64）。
- 安装前建议先退出旧版本；覆盖安装即可，配置与会话数据保存在本地数据库中。

> **升级提示**：本次没有破坏性配置变更，直接覆盖安装即可。
