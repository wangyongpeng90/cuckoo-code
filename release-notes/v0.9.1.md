# v0.9.1 — Cuko API 正式可用

> 0.9.0 的 Cuko API 独立窗口只发过 beta.1，但试用期间发现几处「功能看着有、实际不工作」的硬伤。
> v0.9.1 是 **第一个正式版**：把它们全部修掉，并补上 **Cuko API 市场**。现在这条链路能真正跑起来。

本次亮点速览：

1. **点击会话终于能切换** —— beta.1 里点了没反应，原因是引用了一个没声明的变量。
2. **`cuckoo` 代码块能被正确识别** —— 修了两种围栏写法导致工具整块不执行的问题。
3. **Cuko API 市场** —— 按 GitHub `topic:cuko-api` 发现仓库，一键跳到主页看 README 自行部署。
4. **市场按钮点了没反应已修** —— Cuko 独立窗口补上 `openExternal`。

## 🐞 关键修复

### 1. 点击会话不切换

`switchThread` 里读取输入框草稿时引用了一个**从未声明**的 `runtimeRef`：

```
ReferenceError: runtimeRef is not defined
```

它出现在 `setThreadId(id)` **之前**，所以每次点击都在更新会话 ID 前就抛错，
表现就是「会话列表点了没反应」。`tsc` 本来能报出来（`TS2552`），但 `npm run compile`
只做打包不做这块类型检查，所以漏到了运行时。

修复：补上 `useRef` 声明，并在 `useExternalStoreRuntime` 之后后置赋值；
顺带把「切换会话时保存 / 还原输入框草稿」真正接通（原先 `draftCacheRef` 只写不读，是死缓存）。

### 2. `cuckoo` 代码块不执行（围栏带属性）

模型经常把围栏写成「三个反引号 + cuckoo + `id="58216"`」。旧逻辑取 `slice(3)` 后把整行
`cuckoo id="58216"` 当语言标记，和 `'cuckoo'` 严格比较必然失败 → **块被整条丢弃**。

修复：语言标记只取第一个 token，并识别 `cuckoo-js` / `cuckoo_js` 等变体；
同时统一 CRLF 处理。

### 3. `cuckoo` 代码块不执行（围栏挤在正文行内）

模型偶尔把开围栏贴在正文末尾：

````
……确保复用时不会破坏现有流程。```cuckoo id="c8v5mt"
````

整行 trim 后不以围栏开头，按行首匹配会整块漏掉；等末尾闭合围栏到来时状态错乱，
**整块都不会执行**。

修复：改为扫描行内任意位置的第一个围栏，块外前缀文字直接丢弃。
主进程（`cuko-run-protocol.ts`）与渲染层（`js-detector.ts`）两条路径都已同步修正。

> 这两种写法在实测里都会出现，且都是「AI 输出了代码、界面却静悄悄什么都不做」，
> 排查成本很高。现已各自补上回归用例。

### 4. 市场「进入 GitHub」点击无响应

设置弹窗在 **Cuko 独立窗口**里运行时，该窗口的 preload 暴露的是精简版 `shellAPI`，
**没有 `openExternal`**；而 Cuko 窗口创建时又 `setWindowOpenHandler(() => deny)`
封死了 `window.open` —— 两条路都走不通，点击完全无响应。

修复：给 Cuko 窗口补上 `openExternal`（主进程 `open-external` handler 本来就有）。
按钮尺寸也从撑满整行改为贴合内容宽度。

## 🛒 Cuko API 市场（新增）

设置 → Cuko API →「发现 Cuko API 市场」，按 GitHub `topic:cuko-api` 搜索。

- **唯一真相源是 topic**：搜不到就如实返回空，不做关键词兜底、不做官方精选清单
  —— 宁可诚实地空，也不在用户和事实之间插一层假象。
- 卡片展示仓库名、描述、Star 数与更新时间。
- 点卡片或「**进入 GitHub**」按钮 → 用系统浏览器打开仓库主页，**由你按 README 自行部署**，
  再回到设置页手动「添加模型提供商」填入地址。
- 市场**不会**替你把仓库地址写成 Provider 配置——GitHub 仓库地址不是 API 地址，
  早先那种「一键套用」会把 GitHub URL 填进 `baseUrl`，必然连不上。

### 想让自己仓库出现在市场里

给仓库打上 `cuko-api` topic 即可（About → Topics）。注意拼写完全一致：
`cuko-api` 不等于 `cuckoo-api`。topic 索引有几十秒到几分钟延迟。

## 🔧 其他改动

- **工具契约精简**：`src/tools/api.d.ts` 从 **21.6KB 压到 9.9KB（约 -54%）**。
  每个工具只保留一段简洁 `doc`，删除与 `doc` 重复的 `usage` / `@param` / `@returns` / `@throws`；
  `read` / `edit` 的空白与行号注意事项、`bash` / `pwsh` 的编码与退出码等关键约束保留。
  运行时行为不变，只是提示词更短。
- **从系统提示词移除 `nameConversation` 声明**（功能保留，只是不再展示，省提示词体积）。
- **剪贴板恢复修复**：弃用 `clipboard.write`，恢复时直接 `writeText` 写纯文本，
  并容错 Electron 45 的报错；修复输入框全选越界。
- **用量统计**：补齐缺失时间段，修复切换时间范围后旧请求覆盖新结果的竞态。
- **Electron 44 → 45**，React 18 → 19（Cuko 窗口使用 assistant-ui + Tailwind 4 独立打包）。

## 📦 安装

- **Windows**：下载 `cuckoo-code-win-v0.9.1.exe`（安装版，支持自动更新）。
- **macOS**：下载对应架构的 `.dmg`（Intel 选 x64，Apple Silicon 选 arm64）。
- 安装前建议先退出旧版本；覆盖安装即可，配置与会话数据保存在本地数据库中。

> **升级提示**：本次没有破坏性配置变更，直接覆盖安装即可。
> **如果你装过 0.9.0-beta.1**，本版就是它的正式版——上面四个缺陷在 beta.1 里都存在，已全部修复。
