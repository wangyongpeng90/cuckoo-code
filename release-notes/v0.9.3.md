# v0.9.3 — Cuko 支持 OpenAI 兼容接口

> 这一版最大的变化：Cuko 不再只能连 Cuko API，也能直连**标准 OpenAI Chat Completions 协议**
> （DeepSeek、通义、Kimi、Ollama、OneAPI 等），并且**不用 API Key 也能像以前一样用网页版**。
> 顺带把密钥改成系统级加密存储、修掉几个打断使用的弹窗。

本次亮点速览：

1. **Cuko 接入 OpenAI 兼容接口** —— Provider 选「OpenAI Chat Completions」，聊天里选它的模型就走标准协议。
2. **推理等级可选** —— 模型支持的话，界面上直接切 Off / Low / High / Max，运行中也能改。
3. **输入框下方用量胶囊** —— 点一下看本次会话花了多少 token、缓存命中多少、上下文用了几成。
4. **API 密钥加密存储** —— 用系统级加密（Windows DPAPI / macOS Keychain / Linux libsecret），密钥不再以明文落盘，也不再回传给界面。
5. **修掉两个弹窗问题** —— 关掉启动器窗口后不再弹主进程崩窗；Cuko 窗口的设置确认框终于能正常弹出。

## 🔌 Cuko 接入 OpenAI 兼容接口

以前 Cuko 窗口只能连 Cuko API（有状态、服务端自己维护上下文）。现在多了一种选择：

- 在设置里新建 Provider，**API 协议**选「OpenAI Chat Completions」
- 填地址（如 `https://api.deepseek.com`，末尾带不带 `/v1` 都行）和密钥
- 点「获取可用模型」，再在聊天窗口选模型即可

**和 Cuko API 的区别**：

| | Cuko API | OpenAI 兼容 |
|---|---|---|
| 上下文 | 服务端保存，客户端只发增量 | 客户端每轮重放完整历史 |
| 工具调用 | 同样是对话内联的 `cuckoo` 代码块 | 同左 |
| 前缀缓存 | — | **尽最大努力命中**：历史只在末尾追加，前面一字不变，第二轮起通常 90%+ |

**前缀缓存怎么做到的**：每条消息发送时把原文写入数据库固定下来（`sent_role` / `sent_text`），以后每轮原样重放，绝不重新拼接。思考内容（`reasoning_content`）不回传，只存下来折叠显示。

**自动重试**：网络错误、中途断开、HTTP 429 / 5xx 最多重试 3 次（间隔 2s / 4s / 8s），原样重发同一请求体；400 / 401 / 403 / 404 与用户主动停止不重试。

> **注意**：本版不支持附件（OpenAI 协议会话里发附件会被拦下并提示）。

## 🎚️ 推理等级可选

模型在设置里配了推理档位后，聊天窗口的模型选择器变成两级菜单：

```
模型 >
推理等级 >    ← 新增
```

- 按钮上直接显示当前档位，如 `DeepSeek-V4.1-Flash High`
- 点开可选 Off / Low / High / Max，选中即按会话保存，下一次请求生效
- **运行中也能改**（只改请求参数，不改历史，不影响缓存）
- 档位按会话存，切到别的会话再切回来仍是上次选的

**自动读取接口档位**：刷新模型时会读 DeepSeek `/v1/models` 返回的 `effort` 字段（`supported_levels` + `default_level`），自动填好档位并打开总开关，不用手填。

**接口没给 `off` 时自动补一个**：DeepSeek 只返回 `["low","high","max"]`，但模型能思考就应该能关掉思考。本版会自动补一个 Off 放在最前面；接口自己给了就不重复。

**API 参数值留空 = 用档位名**：设置页那一列留空时，实际发出去的就是档位名本身（如 low 档发 `"reasoning_effort":"low"`）。只有接口要求别的值时才需要填。

## 💊 输入框下方：用量胶囊

输入框下方从「一行三项挤在一起」改成**两个胶囊**：

```
[数据库图标 106K tok · 缓存命中 79.69%]  [上下文 9.3K]
```

- **点第一个胶囊**弹出「Token 用量」面板：标题旁精确合计，下面是缓存命中 / 未缓存输入 / 缓存读取 / 输出（都是精确数字带千分位）
- 点外面 / 按 Esc / 再点一次关闭
- **上下文 ≥ 60%** 时第二个胶囊变橙色，显示 `上下文 82.3K / 128K（64%）`，不拦发送

> 只对 OpenAI 协议会话显示，Cuko 协议会话保持原来的样子。

## 🔐 API 密钥加密存储

以前 API 密钥以**明文**存在 SQLite 里，而且会被读出来回传给界面。这版改成：

**存储层**

- 用 Electron 内置的 `safeStorage` 做系统级加密：
  - **Windows** — DPAPI（绑定当前用户账户）
  - **macOS** — Keychain
  - **Linux** — libsecret（GNOME Keyring / KWallet）
- 数据库里存的是 `enc1$` + base64 密文
- 已有的明文密钥在**下次启动时自动迁移**成密文（幂等，不需要你操作）

**使用层：密钥永不出主进程**

- 界面上只显示掩码（如 `****abcd`）和「已设置」状态
- 编辑 Provider 时密钥框是空的，占位符写「已保存 ****abcd，留空保持不变」
- **留空保存 = 不改原密钥**；要清除点右上角「清除密钥」
- 获取模型、发消息、协议探测全部在主进程解密后使用

**Linux 特别说明**

Linux 上没有可用密钥环时，Electron 会静默回退到「假加密」（硬编码密钥），而且 `isEncryptionAvailable()` 仍然返回 `true`。本版会显式检查后端：

- `gnome_libsecret` / `kwallet` / `kwallet5` / `kwallet6` → 正常加密保存
- `basic_text` / `unknown` → **拒绝保存密钥**，界面红字提示「请安装并启动 gnome-keyring 或 KWallet 后重试」

> **跨机器提醒**：密钥绑定当前机器和账户。把数据库拷到另一台机器，密钥会解不开，需要重新填一次。这是加密的应有行为。

## 🔧 修掉的问题

### 关闭启动器窗口后弹「主进程崩了」

用 `npm start` 启动时，主进程的 stdout 是启动器接的管道。关掉启动器窗口后管道读端消失，之后**任何 `console.log` 都会抛 `EPIPE: broken pipe`**，被 Electron 当成未捕获异常弹窗打断使用（堆栈偶然落在 GrepTool 的日志行上）。

修复：主进程入口与启动器都给 `stdout` / `stderr` 挂了 error 兜底，并把 `console` 的 log / info / warn / error / debug / trace 包了一层——Windows 上 stdout 指向管道时是**同步写**，写失败会同步抛错，光挂钩子兜不住。现在关掉启动器窗口后日志写不出去（这是必然的），但应用不会崩。

### Cuko 窗口的确认框不弹

Cuko 窗口复用了壳页面的设置页，但它的 HTML 骨架只带了 CSS，**没带 `#ck-dialog` 的 DOM**。`ckDialog` 找不到元素时直接当成「确定」，于是保存时的协议确认框静默通过。

修复：补上 DOM，并在缺 DOM 时打 `console.warn` 便于排查。顺带让弹窗正文支持多行显示（`white-space: pre-line`），弹窗宽度 280 → 340px。

### 保存 Provider 时提示协议可能选错

Cuko API 与 OpenAI 兼容接口的 `GET /v1/models` 路径相同但返回格式不同，选错协议要等到发消息才报错，很难定位。

本版在**获取模型后**在协议下拉下方显示黄色提示（带「改为 xxx」「忽略」），**点保存时**再弹一次确认框。没点过「获取可用模型」直接保存时，会先静默探一次接口（只为判断协议，不动模型列表、失败不拦保存）。

> 只提示不自动改——判断依据是返回格式，不保证 100% 准（某些 Cuko 服务商可能照抄 OpenAI 的格式）。

### grep / glob 大目录搜索时主进程 RangeError

搜索超大目录时字符串拼接超过 V8 上限，报 `RangeError: Invalid string length`。改为流式读取，边读边截断。

## 📦 安装

- **Windows**：下载 `cuckoo-code-win-v0.9.3.exe`（安装版，支持自动更新）。

- 安装前建议先退出旧版本；覆盖安装即可，配置与会话数据保存在本地数据库中。
